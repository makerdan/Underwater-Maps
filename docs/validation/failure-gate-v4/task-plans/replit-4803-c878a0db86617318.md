# Complete Failure Gate v4

## What & Why
Finish applying the current Failure Gate v4 contract to BathyScan's existing project-local validation workflow. The merged coordinator reserves durable local IDs and performs a fail-closed authorization preflight, but it cannot yet run a tier, classify complete evidence, or complete an ordinary local task. Implement the missing parts without copying the skill into the repository or claiming control of Replit's Task Board.

## Done looks like
- A reserved local task can be planned, independently reviewed through a pinned committed decision (or a separately approved deterministic policy), activated under exactly one registered tier, and rerun under the same authorization after in-scope edits. Missing approval, another task's plan, stale policy, unauthorized parameters, and tier substitution all deny execution.
- The checked runner executes the approved tier with existing coverage and serialization, and retains tested inputs, relevant environment, raw per-step results, complete reports and discovery, leases, and audit history. A run with a missing adapter, skipped obligation, unknown snapshot, or active conflicting writer cannot count as task evidence.
- Task-local classification distinguishes owned repairs, exact active catalog ignores, three bounded isolation retries, and direct pre-task provenance plus independent corroboration. Unknown failures remain unresolved; catalog promotion and tier/policy changes require separate review.
- A local completion decision accepts only applicable full-tier evidence while coordinating the final input check and terminal write with participating writers. Failed/cancelled tasks release safely without reusing IDs; stuck runs are reconciled without blind duplicate launches.
- A real reviewed local-ID task and a live writer-race check demonstrate the route before a single safe cutover; if review, writer coordination, reports, or an external check is unavailable, ordinary v4 activation stays blocked and the existing route remains authoritative. Documentation states the cooperative and platform boundaries clearly.

## Out of scope
- Editing runtime skill mirrors, installing another skill definition, placing durable deliverables in `.local/`, or changing the deployed API or web product.
- Forging review decisions, reusing the earlier bootstrap approval for new work, claiming authenticated reviewer identity, controlling Replit platform completion/merge, or using platform-managed results as local evidence.
- Weakened validation steps, blanket baseline ignores, remote CI changes, and unrelated product or dependency repairs.

## Steps
1. **Reconcile installation authority** — Compare the current v4 skill and acceptance reference with the tracked capability map and coordinator; record the remaining present, missing, and unavailable interfaces. Obtain a separate real approval for this installation/bootstrap and its selected tier under the prior checked route before executing validation; keep ordinary v4 tasks blocked until cutover.
2. **Complete planning and activation** — Connect reserved local IDs to durable approved plan projections, bounded draft guards and baseline discovery, a real pinned review-decision source, and one-tier activation. Verify plan/registry/parameter/policy digests, versioned audit transitions, and separately reviewed changes without deriving authority from a Replit task number or a caller's assertion.
3. **Execute and record required tiers** — Adapt the existing tier launcher and resource locks into a checked local-ID route with complete versioned report adapters for every registered tier, including heavy preflight and serial suites. Isolate or coordinate relevant writers, record actual dirty/generated/dependency inputs and safe environment identity, require all steps and report/discovery expectations, and keep diagnostic and planning runs distinct from required-tier evidence.
4. **Classify and decide completion** — Apply exact catalog matching, persistent owned-repair obligations, bounded diagnostics, earlier-snapshot provenance, and honest blocked/incomplete/fail/acceptable outcomes. Implement final-input/evidence verification and terminal transition under effective writer coordination, with lease recovery, cancellation, tombstones, audit retention, and policy-change safeguards.
5. **Prove cutover or leave blocked** — Add positive and adversarial tests for reviewer-source stability, task substitution, tier and parameter drift, concurrent allocation/transitions, raw evidence integrity, retry/provenance rules, missing reports, writer races, and recovery. Demonstrate a live reviewed local-ID checked run and live final-write race before replacing the old ordinary-task route in one step; report any unavailable capability rather than treating fixture tests as live proof.

## Pre-existing failures to ignore
None known at plan time for this gate work. The catalog's active raw dependency-audit record applies only to its exact standalone suite/signature and does not authorize an ignore for this task. Treat new failures as potential regressions.

**Flaky-test rule:** A passing retry establishes intermittency, not pre-existing provenance. Use three authorized safe isolation retries where supported and require direct earlier-snapshot evidence plus independent corroboration before classifying an unlisted failure.

## Task-local environment observations
The v4 runner currently records blocked requests without launching checks; reviewer roster is not a verified committed decision source, report adapters and final completion are missing. The prior bootstrap document records approval for that installation only, not for this task's cutover. Do not present either as fresh authorization.

## Validation
**Command:** `test-heavy`
**Why:** Authorization, validation dispatch, evidence integrity, and writer coordination are security and concurrency boundaries; the registered heavy tier covers their existing integration surface.
**Do not escalate:** Run only this authorized tier under a newly approved bootstrap via the prior checked route until v4 cutover is proven. Focused tests are diagnostics, not substitutes; do not treat a blocked or incomplete run as a pass.

## Regression Guard
**Covers:** Unreviewed or substituted tasks executing a tier, incomplete results or stale snapshots passing local completion, and edits racing the final terminal decision.
**Test location:** `scripts/__tests__/failure-gate-v4-coordinator.test.mjs`
**What it checks:** Adversarial activation/run/completion cases deny wrong-task plans, stale or unpinned decisions, tier drift, missing step reports, skipped repairs and catalog mismatches, and intervening writers; accepted runs retain real raw statuses and exactly one authorized tier. Add focused writer-lock integration assertions alongside existing writer-lock tests.
